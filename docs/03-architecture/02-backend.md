# Бэкенд на Supabase

## Из чего состоит

| Компонент Supabase | Для чего используем |
|--------------------|---------------------|
| **Postgres + PostGIS** | Все данные, геозапросы, поиск (pg_trgm, unaccent) |
| **RLS + SQL-функции + триггеры** | Приватность, бизнес-правила, счётчики, лента, очки |
| **PostgREST** | API из схемы: таблицы (свои данные) и RPC-функции (чужие данные, сложные операции) |
| **Auth** | Вход через Apple и Google, сессии, refresh-токены |
| **Storage** | Фото, исходные треки, пакеты правил |
| **Edge Functions** (TypeScript, Deno) | То, что нельзя сделать в SQL: пуши в APNs, удаление аккаунта, подтверждение телефона, сборка пакетов правил |
| **pg_cron + Queues (pgmq)** | Расписания и очереди фоновых задач |
| **Realtime** | Трансляция геопозиции друзьям (1.1) |

Логика живёт в базе (SQL) и в Edge Functions (TypeScript). Своего сервера нет.

## Приватность в базе

Самое важное в бэкенде: ошибка здесь раскрывает чужие секретные места.

1. **RLS включён на всех таблицах**, по умолчанию всё запрещено.
2. **Таблицы с координатами** (`places`, `checkins`, `trips`, `catches`, `media`) напрямую отдают
   **только свои строки**. PostgREST не умеет прятать отдельные колонки для разных зрителей,
   поэтому чужие строки из этих таблиц не отдаются никогда.
3. **Всё чужое — через RPC-функции** (`SECURITY DEFINER`, с `search_path = ''`), например
   `places_in_bbox`, `place_card`, `trip_view`, `user_profile`, `feed`. Каждая функция:
   - проверяет видимость одной общей функцией `can_view(viewer, owner, visibility)` — друзья,
     выбранные друзья (1.1), блокировки;
   - **огрубляет координаты**: приблизительное место → центр со **стабильным** смещением + радиус
     (смещение генерируется один раз и хранится в `fuzz_offset`; случайное при каждом запросе можно
     усреднить и найти точку);
   - заменяет недоступное место на «Секретное место» (`place: null`, `location: null`) и вырезает
     участки трека рядом с ним;
   - обрезает трек зонами приватности автора.
4. **Запись своих данных** — прямой upsert в таблицы (RLS: владелец = `auth.uid()`). Поля, которые
   клиент не должен задавать (`verified`, `status`, счётчики, `fuzz_offset`), закрыты правами на
   колонки и выставляются триггерами:
   - чекин подтверждён, если координаты в радиусе места (считает база);
   - отзыв — только при наличии чекина в месте;
   - публичное место от нового аккаунта → статус `pending` (модерация);
   - запись в ленту (`activities`), начисление очков.
5. **Гости** (роль `anon`) видят только публичные данные через те же RPC.
6. **Тесты pgTAP** — матрица видимости обязательна в CI: зритель (автор, друг, чужой,
   заблокированный, гость) × объект (место, поездка, чекин, улов, медиа) × уровень видимости ×
   приблизительность.
7. Точные координаты и номера телефонов не пишутся в логи и аналитику.

## API: таблицы и RPC

| Через таблицы (PostgREST) | Через RPC-функции |
|---------------------------|-------------------|
| Свои: профиль, места, чекины, поездки, уловы, экипировка, чеклисты, сохранённые, устройства | Места в области карты, карточка места, свежие отчёты, популярные, где были друзья |
| Свои отзывы, сообщения в тредах, реакции, жалобы | Профиль и статистика другого пользователя, поездка и улов друга |
| Публичные: отзывы, треды, статьи, справочники, зоны, правила | Лента, поиск, изменения для синхронизации (`sync_changes`) |
| | Запросы в друзья и их принятие, предложение правки, подписанные ссылки на медиа, `regulations_at` |

**Офлайн и идемпотентность:** ID создаёт клиент (UUIDv7), запись — `upsert` по `id`; повторная
отправка из очереди безопасна. Удаление — мягкое (`deleted_at`), чтобы синхронизация видела удаления.

**Синхронизация:** `sync_changes(since)` возвращает свои объекты, изменённые после метки времени,
включая удалённые; данные друзей приходят через ленту и карточки.

**Изменения схемы:** только добавляющие миграции; если RPC меняется несовместимо — новая версия
функции (`place_card_v2`), старая живёт, пока есть старые сборки приложения.

## Авторизация

### Сейчас: Apple и Google

- **Sign in with Apple** — нативно на iOS, токен передаётся в Supabase (`signInWithIdToken`).
- **Google** — OAuth через Supabase (`signInWithOAuth` + `ASWebAuthenticationSession`), без Google SDK.
- Оба способа можно привязать к одному аккаунту.
- Строка `profiles` создаётся триггером при регистрации; username выбирается на онбординге.
- Сессии и ротация refresh-токенов — встроенные в Supabase Auth.
- **Гостевой режим** — без входа, публичные RPC под ролью `anon`.

### Позже: телефон в момент ценности

Решение 2026-09-29: номер не спрашиваем при регистрации. Просим тогда, когда он даёт пользователю
пользу или нужен для доверия:

| Момент | Зачем номер |
|--------|-------------|
| «Найти друзей из контактов» | Сопоставление с контактами работает только по подтверждённым номерам — иначе можно выдать себя за чужой номер |
| Публикация первого публичного места | Защита от спама: публичные места создают люди с подтверждённым номером |

Для личных мест, чекинов, поездок и уловов номер не нужен.

**Подтверждение** — Edge Functions `phone-start` и `phone-verify`:
1. проверка App Attest (запрос из настоящего приложения) и лимитов (на номер, IP, устройство);
2. Telegram Gateway: `checkSendAbility` → `sendVerificationMessage` ($0,01 за доставленный код);
3. если у номера нет Telegram — SMS (Mobizon, 60,8 ₸) только на казахстанские мобильные номера, с
   дневным лимитом бюджета;
4. в `profiles` сохраняется номер и дата подтверждения.

**Пока подтверждение выключено** (до беты, $0): поиск по контактам скрыт, публичные места новых
аккаунтов проходят премодерацию.

### Удаление аккаунта

Edge Function с сервисной ролью: мягкое удаление на 30 дней → удаление пользователя в Auth, личных
данных и файлов; публичный вклад (отзывы, места) анонимизируется.

## Фоновые задачи

| Механизм | Задачи |
|----------|--------|
| **pg_cron** (SQL по расписанию) | Пересчёт популярности, напоминания о запретах и сборах, очистка (брошенные загрузки, удалённые аккаунты), бейджи |
| **Queues (pgmq) + pg_cron → Edge Function** | Отправка пушей: триггеры кладут задания в очередь, раз в минуту функция `push-worker` их разбирает и отправляет в APNs |
| **Edge Function по событию** | Сборка пакета правил после публикации изменений в админке |

## Медиа

На бесплатном плане нет серверного ресайза картинок, поэтому варианты делает приложение.

1. На устройстве: `full` (длинная сторона 1600 px) и `thumb` (400 px), EXIF удалён; время и
   координаты — отдельными полями.
2. RPC `create_upload` проверяет лимиты и создаёт запись `media`; клиент получает подписанную
   ссылку на загрузку (Storage signed upload URL) и загружает файлы фоновой `URLSession`.
3. Триггер: новые аккаунты → очередь модерации; остальные — сразу `ready`.

Хранение: один приватный бакет `media`; просмотр — по коротким подписанным ссылкам, которые выдаёт
RPC после проверки видимости (пакетом на экран). Отдельные бакеты: `tracks` (исходные треки, только
владелец), `rule-packs` (публичный).

Автоматическая проверка на NSFW — после переезда в РК (воркер на своей VM); до этого — жалобы и
премодерация новых аккаунтов. Видео (1.1) — после переезда или на Pro.

## Правила (регламенты)

- Таблицы `zones` и `regulations`; редактирование — в админке (геометрия, тексты RU/KK/EN,
  источник, дата сверки).
- Публикация → Edge Function собирает **пакет правил** региона (GeoJSON, gzip) →
  `rule-packs/{region}/{version}.json.gz` + манифест `latest.json` → приложение скачивает при обновлении.
- RPC `regulations_at(lon, lat, date)` — для онлайн-проверок (форма улова, флаги браконьерства).

## Уведомления

- Токены устройств — `devices`; уведомления в приложении — `notifications`; настройки по типам и тихие часы.
- Пуши — APNs напрямую из Edge Function (token-based, ключ `.p8` в секретах функций).
- Тексты — шаблоны на языке получателя (RU / KK / EN).

## Лента, поиск, популярность

- **Лента:** триггеры пишут события в `activities`; RPC `feed(cursor)` отдаёт активности друзей с
  учётом видимости.
- **Поиск:** RPC `search(q)` — pg_trgm по названиям на трёх языках с нормализацией казахских букв
  (ә→а, ғ→г, қ→к, ң→н, ө→о, ұ→у, ү→у, һ→х, і→и) и `unaccent`; ранжирование — похожесть ×
  популярность × расстояние.
- **Популярность:** материализованное представление по формуле из
  [плана «Мест»](../02-plan/03-places.md#ранжирование-популярных-mvp), обновление через pg_cron.

## Модерация и геймификация

- Фильтр слов (RU/KK/EN) и лимиты частоты — в триггерах при создании.
- Флаг браконьерства: улов в зоне действующего запрета → очередь модерации.
- Автоскрытие при N жалобах до решения модератора.
- Очки — `points_ledger` (только добавление, пишут триггеры после прохождения проверок).

## Админка

- React + Refine + провайдер данных `@refinedev/supabase`; вход — Supabase Auth, роли
  (администратор, редактор, модератор) в `profiles.role`, проверки в RLS и RPC.
- Редактор геометрий — MapLibre GL JS + Terra Draw; статьи — Markdown с фото; вкладки языков и
  статус перевода; журнал действий (триггеры).
- Хостинг — Cloudflare Pages (статический сайт; данные идут из браузера напрямую в Supabase).

## Типы и тесты

- Источник правды — миграции в `supabase/migrations`.
- Типы: `supabase gen types` для TypeScript (админка, Edge Functions); для Swift — модели в `Core`
  (генерацию Swift-типов проверим в спайке S3).
- Тесты: pgTAP (`supabase test db`) для RLS, RPC и триггеров; Deno-тесты для Edge Functions.
  Локально весь стек поднимается `supabase start`.
