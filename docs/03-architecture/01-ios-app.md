# iOS-приложение

## Базовые решения

| Параметр | Решение |
|----------|---------|
| Минимальная версия | **iOS 26** — требование DesignKit (Liquid Glass) |
| Язык | Swift 6 language mode со строгой проверкой конкурентности для модулей приложения (DesignKit остаётся в Swift 5 mode — это нормально для зависимости) |
| UI | SwiftUI; UIKit — только в обёртках (карта) |
| Проект | XcodeGen (`project.yml`), как в DesignKit Gallery — без конфликтов в `.pbxproj` |
| Архитектура экранов | `@Observable` MVVM: View + ViewModel (`@MainActor`) + сервисы за протоколами |
| Зависимости (SPM) | DesignKit, MapLibre Native, GRDB, **supabase-swift** (вход, таблицы, RPC, Storage, Realtime), Nuke (загрузка и кэш картинок) |

Зависимостей — минимум. Google Sign-In SDK не берём: вход через Google — OAuth через Supabase
(`ASWebAuthenticationSession`). Краши — Xcode Organizer и MetricKit (бесплатно, встроено).

## Модули

Локальные SPM-пакеты в `ios/Packages/`. Зависимости — только сверху вниз.

```
App (Dalada)          сборка зависимостей, TabView, навигация, диплинки
  │
Features              Onboarding · Auth · Profile · Social · Map · Places · Tracking ·
  │                   Lifehacks · Settings
  │
Services              Backend · Persistence · Sync · Location · MapEngine · Media ·
  │                   Regulations · Contacts · Notifications · Analytics
  │
Core + UI             Core (доменные модели, форматтеры, i18n-хелперы) · DaladaUI (компоненты)
  │
External              DesignKit · MapLibre · GRDB · supabase-swift · Nuke
```

| Модуль | Отвечает за |
|--------|-------------|
| **Core** | Доменные типы (`Place`, `Trip`, `Catch`, `Visibility`…), единицы измерения, форматтеры, идентификаторы (UUIDv7) |
| **DaladaUI** | Компоненты приложения поверх DesignKit: карточки места/поездки/улова, рейтинг, бейдж видимости, строка чеклиста, обобщённая карточка статистики. Универсальные — со временем переносим в DesignKit |
| **Backend** | Обёртка над supabase-swift: вход, таблицы, RPC, подписанные ссылки Storage; адрес и ключ бэкенда — из удалённой конфигурации (см. ниже). Фичи не знают о Supabase — только о протоколах |
| **Persistence** | GRDB: схема, миграции, репозитории, наблюдение за изменениями |
| **Sync** | Очередь операций (outbox), загрузка медиа и треков, получение изменений |
| **Location** | Запись трека (TrackingEngine), следование по маршруту, Live Activity |
| **MapEngine** | Обёртка над MapLibre: стили, слои, кластеры, офлайн-пакеты. Изолирует SDK — замена на Mapbox не трогает фичи |
| **Media** | Выбор и съёмка фото, сжатие, удаление EXIF, превью |
| **Regulations** | Офлайн-движок правил: «что действует в этой точке на эту дату» |
| **Contacts** | Доступ к контактам (в т.ч. ограниченный доступ iOS 18+), нормализация номеров, сопоставление с сервером |
| **Notifications** | Регистрация в APNs, разрешения, локальные напоминания (сборы, запреты) |
| **Analytics** | Продуктовые события → свой бэкенд |

## Экраны и навигация

- **TabView** (iOS 26): Главная · Карта · Места · Лайфхаки · Профиль (`AppRouter`; вкладки «+» нет —
  добавления в контексте разделов, см. `docs/04-beta/M10-home.md`).
- У каждой вкладки свой `NavigationStack` с типизированными маршрутами (`enum Route`) и
  `@Observable Router`. Диплинки и пуши приводятся к маршрутам.
- Активная поездка — `tabViewBottomAccessory` (мини-плеер над таб-баром).
- Страница места с карты — нижняя шторка (`presentationDetents`).
- Зависимости передаются через `Environment` (`AppDependencies` с протоколами сервисов) —
  в тестах и превью подменяются на фейки.
- Общий тип состояния экрана: `loading / content / empty / error` → `EmptyStateView` из DesignKit.

## Данные и офлайн

**Главное правило:** экраны читают **только локальную БД**. Сеть обновляет БД, БД обновляет экраны
(`ValueObservation` из GRDB → `AsyncSequence`). Так офлайн работает без отдельной логики.

### Локальная БД (GRDB / SQLite)

| Группа таблиц | Что хранит |
|---------------|------------|
| Свои данные | Поездки, точки трека, чекины, уловы, свои места, экипировка, чеклисты, сохранённые/любимые |
| Кэш общего | Публичные места рядом и просмотренные, отзывы, треды, профили друзей, лента (с TTL) |
| Справочники | Виды рыб, типы мест, атрибуты, категории экипировки — с переводами |
| Офлайн-контент | Статьи, шаблоны чеклистов, пакеты правил, метаданные офлайн-карт |
| Служебные | Очередь операций (outbox), загрузки медиа, курсоры синхронизации, настройки |

Для запросов «места в видимой области карты» — пространственный индекс SQLite R*Tree.

### Очередь операций (outbox)

- Всё, что пользователь создаёт или меняет, сначала пишется в БД и в очередь.
- Идентификаторы создаёт клиент (UUIDv7) → повторная отправка безопасна: запись идёт `upsert`
  по `id` в таблицы Supabase (RLS пускает только владельца).
- Порядок учитывает зависимости: новое место → чекин в нём → улов в чекине → фото.
- Запуск обработки: приложение на переднем плане, появилась сеть (`NWPathMonitor`),
  фоновые задачи (`BGTaskScheduler`). Повторы с экспоненциальной задержкой.
- В интерфейсе — «ожидает отправки» у объекта и общий индикатор.

### Медиа

1. На устройстве делаются два варианта — `full` (1600 px) и `thumb` (400 px), EXIF удаляется;
   время и координаты передаются отдельными полями. (На бесплатном плане Supabase нет серверного
   ресайза.)
2. RPC `create_upload` → подписанная ссылка Storage → загрузка через фоновую `URLSession`
   (переживает выгрузку приложения).
3. Просмотр чужих фото — по подписанным ссылкам, которые выдаёт RPC после проверки видимости;
   кэш на устройстве — Nuke.
4. Загрузка только по Wi-Fi — настройка пользователя.

### Получение изменений

- RPC `sync_changes(since)` — изменения своих объектов (включая удалённые) с прошлой метки времени.
- Лента и данные друзей — RPC `feed(cursor)`, кэшируются в локальной БД.
- Публичные места — RPC `places_in_bbox` по области карты, кэшируются в локальной БД.
- Конфликты: для своих объектов побеждает последняя правка; общие места меняются только через
  «предложить правку».

## Запись трека (TrackingEngine)

| Задача | Как |
|--------|-----|
| Получение координат | `CLLocationUpdate.liveUpdates(_:)` с конфигурацией по активности (рыбалка — `.otherNavigation`, поход — `.fitness`) |
| Работа в фоне | `CLBackgroundActivitySession` — достаточно разрешения «При использовании», без «Всегда» |
| Авторизация | `CLServiceSession` (iOS 18+) на время записи |
| Автопауза | Признак неподвижности из `CLLocationUpdate` + порог по времени; на рыбалке — мягкие настройки |
| Фильтрация | Отбрасываем точки с плохой точностью (> 50 м в «Точном», > 100 м в «Экономном») и выбросы скорости |
| Набор высоты | Барометр (`CMAltimeter`) — GPS-высота слишком шумная |
| Надёжность | Каждая точка сразу пишется в SQLite; машина состояний `idle → recording ⇄ paused → finishing → saved`; при запуске приложения незавершённая поездка восстанавливается |
| Live Activity | ActivityKit, обновление из приложения раз в 10–15 с: время, дистанция, кнопки паузы и стопа |
| Отправка | Трек кодируется (polyline с точностью 6 знаков + массивы времени и высоты), сжимается gzip, уходит через outbox |

Цели по батарее проверяем в спайке S2.

## Карта (MapEngine)

- `DaladaMapView` — SwiftUI-обёртка над `MLNMapView`.
- Источники данных на карте:
  - базовая карта — стиль «Outdoor» или «Спутник» (см. [03-maps-geo.md](03-maps-geo.md));
  - места (публичные, свои, друзей) — GeoJSON из локальной БД, с кластеризацией MapLibre;
  - запреты, нацпарки, погранзона — GeoJSON из пакета правил;
  - треки — GeoJSON из локальной БД.
- Офлайн-пакеты — `MLNOfflineStorage` + `MLNTilePyramidOfflineRegion` по заранее заданным регионам;
  прогресс, пауза, обновление, удаление.

## Правила офлайн (Regulations)

- Пакет правил на регион: упрощённые границы зон + ограничения на год; скачивается вместе с
  офлайн-картой, обновляется при запуске, если вышла новая версия.
- Запрос «что действует здесь сегодня»: отбор по R*Tree → точка внутри полигона → фильтр по датам.
- Используется на карте, на странице места, в форме улова и в напоминаниях.

## Навигация

- **Следование по треку:** проекция позиции на ближайший отрезок, пройдено и осталось, уход с
  маршрута (дальше ~50 м дольше ~20 с) → вибрация и локальное уведомление; «обратный путь» —
  тот же трек в обратную сторону. Работает офлайн.
- **Внешние навигаторы** до точки подъезда: Apple Maps, 2ГИС, Яндекс Навигатор, Google Maps
  (URL-схемы — в [03-maps-geo.md](03-maps-geo.md#внешние-навигаторы)); показываем только установленные.

## Вход и аккаунт

- **Регистрация:** Sign in with Apple (нативно, `AuthenticationServices` → `signInWithIdToken`) и
  Google (OAuth через Supabase). Сессию и токены хранит supabase-swift (Keychain).
- **Гость:** карта, публичные места, статьи, правила — без входа.
- **Телефон — позже**, в момент ценности: «Найти друзей из контактов» и публикация первого
  публичного места. Экран: код страны (+7), маска; перед запросом кода — **App Attest**
  (`DCAppAttestService`); код приходит в Telegram (или SMS); автоподстановка
  `textContentType(.oneTimeCode)` для SMS. Пока подтверждение выключено — эти экраны скрыты.

## Удалённая конфигурация

Адрес бэкенда, публичный ключ Supabase, адреса тайлов и флаги функций (например, «подтверждение
телефона включено») приложение берёт из `https://dalada.app/config.json` (кэшируется, есть
значения по умолчанию в сборке). Так переезд Supabase в РК и включение функций не требуют
обновления приложения. После переезда пользователи один раз входят заново.

## Контакты

- Доступно после подтверждения телефона (сопоставление только по подтверждённым номерам).
- Запрос доступа к контактам — только по действию «Найти друзей», с объяснением.
- Поддержка ограниченного доступа iOS 18+ (пользователь выбирает часть контактов).
- Номера нормализуются в E.164 и отправляются пакетами в Edge Function `contacts-match`; она
  отвечает совпадениями и **не хранит** адресную книгу.

## Локализация

- String Catalog (`Localizable.xcstrings`): `ru`, `kk` (кириллица), `en`. Ключи — смысловые
  (`profile.stats.trips`), как в Tenra/DesignKit (`tab.add`).
- Плюрализация — через каталог (правила для русского и казахского различаются).
- Язык интерфейса — системная настройка языка приложения (Настройки iOS → Dalada → Язык);
  в приложении — кнопка, открывающая эти настройки.
- Язык контента с сервера — заголовок `Accept-Language` из текущей локали.
- Проверить в спайке: покрытие казахских букв (ә, ғ, қ, ң, ө, ұ, ү, һ, і) в Inter и в шрифтах подписей на карте.

## Дизайн-система

- DesignKit подключаем как SPM-зависимость с точной версией (`exact: "0.2.0"` в
  `ios/Packages/DaladaKit/Package.swift`). Новая версия приходит только сменой номера; CI DesignKit
  собирает Dalada с каждым своим изменением, так что сломать сборку Dalada незаметно нельзя.
- Обновление автоматическое: workflow **DesignKit update** (`.github/workflows/designkit.yml`) раз в
  сутки сверяет версию с последним релизом DesignKit, при новом релизе собирает приложение и тесты
  пакета и, если всё зелёное, коммитит новую версию в `main`. Вручную — Actions → DesignKit update
  → Run workflow.
- Правила и каталог компонентов — в DesignKit: `CLAUDE.md`, `docs/design-system.md`,
  `docs/localization-keys.md` (ключи, которые компоненты берут из нашего `Localizable.xcstrings`).
  Галерея компонентов с темой Dalada — в TestFlight («DesignKit Gallery»).
- **Акцент Dalada — зелёный** (`AccentColor` в `Assets.xcassets`: светлая тема #2E8B57, тёмная
  #3CB371). `AppBootstrap.configure()` передаёт его в DesignKit (`DesignKitTheme.accent`), и тот же
  цвет красит системные элементы (`ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME`).
- **Ещё нужно в DesignKit:** «outdoor»-палитра для категорий мест и статусов правил — токенами.
- Компоненты приложения — в `DaladaUI`; универсальные (карточка статистики со значением и единицей,
  рейтинг, строка-чекбокс) — кандидаты в DesignKit.
