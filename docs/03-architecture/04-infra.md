# Инфраструктура

## Принципы

1. Всё с персональными данными — в облаке на территории РК.
2. Простая топология: VM + управляемый PostgreSQL + S3. Docker Compose, без Kubernetes.
3. Переносимость: стандартный Postgres, S3-совместимый API, Docker-образы — провайдера можно сменить.
4. Всё воспроизводимо из репозитория (`infra/`): конфигурация, скрипты деплоя, миграции.

## Провайдер в РК

| Провайдер | ЦОД | Что есть (по открытым данным) | Проверить |
|-----------|-----|-------------------------------|-----------|
| **PS Cloud Services** (ps.kz) | Алматы, Астана | VM, управляемые PostgreSQL/MySQL, S3 (совместим с S3 и Swift), Kubernetes, балансировщики; ISO 27001, PCI DSS | PostGIS в управляемом PostgreSQL, PITR, CDN, цены |
| **Yandex Cloud**, регион kz1 | Караганда | Отдельный регион и консоль; Object Storage (`storage.yandexcloud.kz`) | Какие сервисы доступны в kz1 (управляемый PostgreSQL с PostGIS), цены в ₸ |
| **VK Cloud KZ** | — | Базы данных как сервис | ЦОД, PostGIS, S3 |
| **Servercore KZ** | Алматы (Tier III) | Облачные базы PostgreSQL, от ~3 945 ₸ за vCPU в месяц | PostGIS, S3 в Алматы |

Действие: запросить у 2–3 провайдеров подтверждение PostGIS + `pg_trgm` + `unaccent`, восстановление
на момент времени (PITR), наличие CDN в РК и коммерческое предложение. Если PostGIS в управляемой
базе нет — PostgreSQL на отдельной VM с автоматическими бэкапами (больше работы по эксплуатации).

## CI/CD

| Что | Где | Шаги |
|-----|-----|------|
| Бэкенд и админка | GitHub Actions | Линт → тесты (Testcontainers + PostGIS) → проверка, что `openapi.yaml` актуален → Docker-образ → деплой на staging автоматически, на production — вручную (кнопка) |
| Миграции БД | Шаг деплоя | Применяются до запуска новой версии; только обратно совместимые изменения |
| iOS | Xcode Cloud (25 часов сборки в месяц входят в Apple Developer Program) | Сборка → тесты → TestFlight; генерация API-клиента из `openapi.yaml` при сборке |
| Тайлы | GitHub Actions по расписанию (раз в месяц) или на VM | Planetiler → MBTiles → загрузка в S3 → перезапуск Martin |

## Мониторинг

- **Ошибки:** GlitchTip (open source, принимает события от Sentry SDK) — и iOS (sentry-cocoa), и
  бэкенд. Хранится в РК.
- **Логи:** pino JSON → логирование провайдера или Loki + Grafana на VM. Без номеров телефонов и
  точных координат.
- **Метрики и доступность:** проверки `/health` снаружи, оповещения в Telegram владельцу;
  метрики API (задержки, ошибки), очередь задач, расход на SMS.
- **Продуктовая аналитика:** события → таблица `events` → Metabase (дашборды по воронкам и метрикам из плана).
- **Краши iOS:** Xcode Organizer и MetricKit — бесплатно, плюс GlitchTip.

## Безопасность

- TLS везде; база и S3 не доступны из интернета напрямую (кроме presigned URL).
- Секреты — в менеджере секретов провайдера или зашифрованы в репозитории (SOPS); ключи S3 — с
  минимальными правами на свой бакет.
- App Attest перед отправкой кодов; лимиты на уровне Caddy и API.
- Refresh-токены и коды — только хеши; журнал действий админов.
- Зависимости — Dependabot; образы — сканирование уязвимостей в CI.
- Удаление аккаунта и экспорт данных — по запросу пользователя.

## Бэкапы и восстановление

| Что | Как | Цель |
|-----|-----|------|
| PostgreSQL | PITR провайдера (7–14 дней) + ежедневный дамп в отдельный бакет с версионированием | Потеря данных ≤ 15 мин, восстановление ≤ 4 ч |
| Медиа и треки | Версионирование S3 | Восстановление удалённого по ошибке |
| Конфигурация | Репозиторий `infra/` | Новая VM поднимается скриптом |

Раз в квартал — пробное восстановление на staging.

## Данные за пределами РК

Нужна проверка юристом и пункты в согласии на обработку ПД.

| Сервис | Что получает | Зачем |
|--------|--------------|-------|
| Apple | APNs-токены устройств, данные Sign in with Apple | Пуши, вход |
| Google | Данные входа через Google (если пользователь выбрал) | Вход |
| Telegram | Номер телефона и код | Доставка кода входа |
| Провайдер спутника | Запросы тайлов (IP-адрес) | Спутниковый слой |
| GitHub, Xcode Cloud | Исходный код, без ПД | Разработка |

Mapbox и сторонняя аналитика не используются — геолокация пользователей не покидает РК.
