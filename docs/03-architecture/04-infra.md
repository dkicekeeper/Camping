# Инфраструктура

## Принципы

1. **$0 до беты.** Бесплатные планы Supabase, Cloudflare, GitHub, Xcode Cloud.
2. **Персональные данные — в РК к публичному запуску.** До этого — Supabase Cloud (Франкфурт) с
   согласием тестеров; затем self-hosted Supabase в Казахстане.
3. **Переносимость.** Supabase — open source; схема и функции — в миграциях репозитория; адрес
   бэкенда приложение берёт из удалённой конфигурации.
4. **Всё воспроизводимо из репозитория:** миграции, Edge Functions, стили и сборка тайлов, админка.

## Где что живёт

| Что | Сервис | Данные |
|-----|--------|--------|
| База, вход, файлы, API, функции, фоновые задачи | **Supabase Cloud Free**, регион `eu-central-1` (Франкфурт) | ПД пользователей |
| Тайлы карты | **Cloudflare R2** + кэш Cloudflare (`tiles.dalada.app`) | Без ПД |
| Админка | **Cloudflare Pages** (статический сайт) | Без ПД (данные идут в Supabase из браузера) |
| `config.json`, лендинг, `apple-app-site-association` | Cloudflare Pages (`dalada.app`) | Без ПД |
| Спутник | ArcGIS Location Platform (бесплатный план) | Без ПД (запросы тайлов) |
| Код, CI | GitHub (Actions) | Без ПД |
| Сборки iOS | Xcode Cloud → TestFlight | Без ПД |

Проекты Supabase (бесплатно — 2 активных): `dalada-dev` (разработка) и `dalada-beta` (бета).
Локальная разработка — `supabase start` (весь стек в Docker на компьютере).

## Лимиты бесплатного Supabase

| Ресурс | Лимит Free | На что хватит | Что делать при приближении |

| Файлы | 1 ГБ | ~3 000 фото (1600 px + превью 400 px, ~300 КБ на фото) | Сильнее сжимать; Pro или переезд |

| Активные пользователи (Auth) | 50 000 в месяц | С запасом | — |
| Пауза проекта | После 7 дней без активности | Для dev — нормально; бета держит проект активным | Pro на время беты при необходимости |

**Pro ($25 в месяц)** включаем, только если бета упрётся в лимиты или понадобятся встроенные бэкапы.

## CI/CD

| Что | Где | Шаги |
|-----|-----|------|
| База | GitHub Actions | Локальный стек Supabase в CI → миграции → тесты pgTAP (матрица видимости) → `supabase db push` в `dalada-dev` автоматически, в `dalada-beta` — вручную |
| Edge Functions | GitHub Actions | Deno-тесты → `supabase functions deploy` |
| Админка | Cloudflare Pages | Сборка и деплой из ветки `main` |
| iOS | Xcode Cloud (25 часов сборки в месяц входят в Apple Developer Program) | Сборка → тесты → TestFlight |
| Тайлы | GitHub Actions по расписанию (раз в месяц) | Planetiler → MBTiles → файлы `z/x/y` → загрузка в R2 (rclone) |

Бесплатные минуты GitHub Actions для приватного репозитория — 2 000 в месяц; сборки iOS идут в
Xcode Cloud и эти минуты не тратят.

## Мониторинг

- **Бэкенд:** логи и отчёты Supabase (API, Postgres, Auth, Edge Functions), советник по
  производительности и безопасности в панели Supabase.
- **iOS:** Xcode Organizer (краши, зависания, энергопотребление) и MetricKit — бесплатно.
- **Аналитика:** анонимные продуктовые события — TelemetryDeck (бесплатный план) или своя таблица в
  Supabase (решим на Этапе 4). Без номеров телефонов и точных координат.
- **Доступность:** бесплатная внешняя проверка `config.json` и API, оповещение в Telegram.

## Бэкапы

| Что | Как |
|-----|-----|
| База | Ежедневно GitHub Actions: `supabase db dump` → шифрование (age) → отдельный бакет R2 с версионированием; хранение 30 дней |
| Файлы Storage | Еженедельная копия в R2 (rclone) |
| Код и схема | Репозиторий |

Раз в месяц — пробное восстановление дампа в локальный Supabase.

## Безопасность

- RLS на всех таблицах; тесты видимости в CI; советник безопасности Supabase без предупреждений.
- Сервисный ключ (`service_role`) — только в Edge Functions и секретах CI, никогда в приложении и админке.
- Админы — отдельные аккаунты с ролями; журнал действий.
- Секреты функций (ключ APNs, Telegram Gateway) — в секретах Supabase.
- App Attest и лимиты перед отправкой кодов подтверждения.
- Dependabot для зависимостей админки и функций.

## Переезд в Казахстан (перед публичным запуском)

**Когда:** после закрытой беты, до ~20 мая 2027. Репетиция — спайк S4.

**Куда:** self-hosted Supabase (Docker Compose) на VM в РК + S3-хранилище в РК для Storage.
Кандидаты:

| Провайдер | ЦОД | Что есть (по открытым данным) | Проверить |
|-----------|-----|-------------------------------|-----------|
| PS Cloud Services (ps.kz) | Алматы, Астана | VM, управляемые базы, S3, Kubernetes | Цены, CDN |
| Yandex Cloud, регион kz1 | Караганда | VM, Object Storage | Цены в ₸ |
| Servercore KZ | Алматы (Tier III) | VM, облачные базы, от ~3 945 ₸ за vCPU в месяц | S3 в Алматы |
| VK Cloud KZ | — | VM, базы данных | ЦОД, S3 |

Размер на старте: VM 4 vCPU / 8 ГБ / 100 ГБ SSD + S3 → ~40–80 тыс. ₸ в месяц (оценка).
На этой же VM потом живут воркер медиа (проверка NSFW, видео) и Valhalla (роутинг 1.1).

**Как (по официальной инструкции Supabase «Restore a Platform Project to Self-Hosted»):**
1. Поднять self-hosted Supabase на VM, Storage — на S3 провайдера.
2. Перенести базу через Supabase CLI: роли, схема, данные.
3. Скопировать файлы Storage (rclone), задеплоить Edge Functions, перенести секреты и pg_cron.
4. Обновить `config.json` — приложение переключится на новый адрес.
5. Пользователи **один раз входят заново** (у нового сервера другой JWT-секрет; аккаунты сохранены).
6. Удалить данные из Supabase Cloud после проверки.

**Что появится в эксплуатации:** обновления Supabase и ОС, мониторинг VM, бэкапы Postgres
(WAL-G или pgBackRest в S3). Это главная цена переезда для одного разработчика.
