# M6. Готовность к бете

> Статус: **M6a (жалобы, блокировка, фильтр грубых слов) и M6b (удаление аккаунта) — в сборке 107,
> M6c (документы, поддержка, согласие) — в сборке 108. M6d (пуши) — код готов, нужна настройка
> ключа APNs и секретов (ниже).** Дальше: M6e — наполнение (150+ мест).

Для внешней беты (Beta App Review) Apple требует для пользовательского контента: фильтр
нежелательного контента, жалобы, блокировку, контакт для связи и реакцию на жалобы (Guideline
1.2), удаление аккаунта из приложения (5.1.1(v)) и ссылку на политику конфиденциальности.

| Часть | Что | Статус |
|-------|-----|--------|
| **M6a** | Жалобы на места, отчёты, поездки, отзывы, обсуждения, ответы и людей; «Заблокировать автора» у чужого контента; фильтр грубых слов | На проверке (107) |
| **M6b** | Удаление аккаунта из приложения | На проверке (107) |
| **M6c** | Согласие при регистрации, политика конфиденциальности, условия и правила сообщества, поддержка (RU / KK / EN) | На проверке (108) |
| **M6d** | Пуши (базово): ответ в обсуждении, запрос в друзья, запрос принят | Код готов, нужна настройка |
| **M6e** | 150+ мест к бете | Владелец продукта |

## M6a. Жалобы, блокировка, фильтр

### Что делает приложение

| Где | Что |
|-----|-----|
| Отзыв, ответ в обсуждении, отчёт (чекин) в карточке места | «…» → «Пожаловаться» или «Заблокировать @автора»; после блокировки его отзывы и отчёты сразу пропадают с экрана |
| Карточка чужого места, обсуждение, чужая поездка | «…» в правом верхнем углу — то же |
| Профиль человека | «…» → «Пожаловаться» (рядом с «Заблокировать») |
| Жалоба | Причина (спам, оскорбления, непристойное, браконьерство, раскрыто чужое место, неправда, другое) и подробности; «Жалоба отправлена» |
| Любой текст, который видят другие | Грубые слова не сохраняются: «Уберите, пожалуйста, грубые слова». Проверяются имя и username, названия и описания мест, заметки чекинов, поездки, отзывы, обсуждения и ответы. Личное («только я») не проверяется |

Гостю «…» не показывается. Блокировка — как и раньше: заблокированные не видят друг друга,
дружба и запросы удаляются; список — «Профиль» → «Друзья» → «Заблокированные».

### Как редакция разбирает жалобы

Supabase Studio → Table Editor → схема `private` → **`moderation_queue`**: открытые жалобы по
объектам (сколько, причины, комментарии), сначала — с большим числом жалоб.

1. Найдите объект по `target_kind` и `target_id` (`place` → `places`, `checkin` → `checkins`,
   `trip` → `trips`, `review` → `reviews`, `thread` → `threads`, `post` → `thread_posts`,
   `user` → `profiles`).
2. Нарушает правила — поставьте объекту `deleted_at` (сейчас). Человеку, который систематически
   нарушает, — удалите пользователя в Authentication → Users (всё его удалится каскадом).
3. В `public.reports` отметьте жалобы: `status` = `resolved` (приняли меры) или `dismissed`
   (нарушения нет), `resolved_at`, при желании `resolution_note`.

Apple ждёт реакции на жалобы в течение суток — приложение так и обещает после отправки жалобы.

**Фильтр слов** — таблица `private.banned_patterns` (регулярные выражения PostgreSQL, текст в
нижнем регистре; `\m` — начало слова). Добавить слово — новая строка; проверить —
`select private.has_banned_words('текст')` в SQL Editor.

### Код

- База: `migrations/…_moderation.sql` — `reports` (закрыта для клиента) и `report_content(kind,
  id, reason, note)`: жалоба только на видимое и не на своё, одна на объект, 20 в сутки (`DL003`);
  `private.moderation_queue`; фильтр `private.banned_patterns`, `private.has_banned_words` и
  триггеры `*_word_filter` (`DL005`). Тесты — `15_moderation.test.sql` (26 проверок), всего — 348.
- `DaladaCore/Moderation.swift` (виды и причины жалоб), `CommunityRefusal.badWords`;
  `Backend/ModerationAPI.swift`; отказ `DL005` в офлайн-очереди — окончательный, с понятным текстом.
- `AppFeature/ModerationViews.swift` — меню «…» и экран жалобы; подключены в отзывах, обсуждениях,
  ответах, отчётах, карточке места, поездке и профиле.

### Как проверить

Нужны два аккаунта (второй телефон или выйти и войти другим).

1. Аккаунтом Б оставьте отзыв или ответ в обсуждении публичного места.
2. Аккаунтом А: у отзыва «…» → «Пожаловаться» → «Спам или реклама» → «Отправить» → «Жалоба
   отправлена». В Studio жалоба в `private.moderation_queue`.
3. Там же «…» → «Заблокировать» → отзывы Б пропали; в «Друзья» → «Заблокированные» — Б.
4. В названии нового публичного места или в заметке чекина напишите грубое слово → «Уберите,
   пожалуйста, грубые слова». В личном месте («только я») — сохраняется.
5. Профиль → имя с грубым словом → не сохраняется.

### Что нужно от владельца продукта

- Решение о **сроке реакции на жалобы**: в приложении и в условиях написано «в течение суток».

## M6b. Удаление аккаунта

### Что делает приложение

«Профиль» → «…» → **«Аккаунт»**: username и имя, «Выйти», **«Удалить аккаунт»** с описанием, что
удалится, и подтверждением «Удалить аккаунт навсегда?».

Удаление:
1. Приложение удаляет свои фото из бакета `media` (папка `<id пользователя>/`).
2. RPC `delete_my_account` удаляет пользователя в Auth, а с ним каскадом — профиль, места, чекины,
   уловы, поездки, отзывы, обсуждения и ответы, реакции, друзей и запросы, блокировки, свои
   жалобы, экипировку и чеклисты. Жалобы других людей на этого человека остаются (без ссылки).
3. На телефоне стираются сохранённые данные аккаунта, офлайн-очередь и списки; человек — снова
   гость.

Без сети удаление не начинается (ошибка, аккаунт цел). Сразу и без восстановления; мягкое удаление
на 30 дней и обезличивание публичных отзывов — после беты. Удалённое обсуждение уносит с собой и
ответы других людей.

### Код

- База: `migrations/…_delete_account.sql` — `delete_my_account()`; тесты — `16_delete_account.test.sql`
  (9 проверок), всего — 357. Сквозная проверка против локального Supabase: фото удалены из
  хранилища, пользователь — из Auth, повторный вход невозможен.
- `Backend/AccountAPI.swift`; `SessionStore.deleteAccount()`; `OutboxStore.removeAll(owner:)`,
  `OwnRecordStore.removeAll(account:)`; `AppFeature/AccountView.swift`.

### Как проверить

Лучше на тестовом аккаунте (например, второй Apple ID или Google).

1. Войдите, создайте место, чекин с фото, предмет экипировки.
2. «Профиль» → «…» → «Аккаунт» → «Удалить аккаунт» → «Удалить навсегда».
3. Профиль — снова «Войти»; в Studio пользователя нет в Authentication → Users, в `media` нет его
   папки, его места и чекины пропали.
4. Войдите тем же Apple ID / Google снова — это новый аккаунт с выбором username.

## M6c. Документы, поддержка, согласие

### Страницы (GitHub Pages, как в Tenra)

Исходники — `docs/public` (одна страница на документ, разделы на русском, казахском и английском);
публикует workflow **Pages** при каждом изменении `docs/public` в `main`:

| Страница | Адрес |
|----------|-------|
| Политика конфиденциальности | https://dkicekeeper.github.io/Dalada/privacy-policy.html |
| Условия использования и правила сообщества | https://dkicekeeper.github.io/Dalada/terms-of-use.html |
| Поддержка и частые вопросы | https://dkicekeeper.github.io/Dalada/support.html |

Язык — якорем: `…#ru`, `…#kk`, `…#en`. Почта поддержки — dakacom@gmail.com.

**Один раз:** GitHub → репозиторий Dalada → Settings → Pages → Build and deployment → Source:
**GitHub Actions**. Потом Actions → Pages → Run workflow (или любой пуш `docs/public` в `main`).

**App Store Connect** → TestFlight → Test Information: Feedback Email — dakacom@gmail.com, Privacy
Policy URL — адрес политики выше. Для App Store позже — те же ссылки и Support URL.

Что написано в политике: какие данные собираем (аккаунт, профиль, места, чекины, уловы, фото,
поездки, отзывы, обсуждения, реакции, жалобы, экипировка, геопозиция — в фоне только во время
записи поездки), зачем, кто что видит, хранение в Supabase во Франкфурте (за пределами РК — с
согласия), сторонние сервисы (Supabase, Apple, Google, OpenFreeMap), удаление аккаунта, права,
возраст 16+. В условиях — правила сообщества, модерация (жалобы — в течение суток), справочный
характер правил и статей, отказ от гарантий. Казахский текст — черновик на вычитку; юридически
документы стоит показать юристу до публичного запуска.

### Что делает приложение

- **Согласие.** После входа (и если документы существенно изменились) — экран «Условия и
  конфиденциальность»: коротко о том, где хранятся данные и кто их видит, ссылки на условия и
  политику, переключатель «Я принимаю … и соглашаюсь на хранение моих данных за пределами
  Казахстана», «Продолжить»; или «Выйти». Затем — выбор username. Версия и время согласия — в
  профиле (`terms_version`, `terms_accepted_at`, записывает только `accept_terms`). Без сети экран
  не показывается (спросим, когда профиль загрузится с сервера).
- **Ссылки.** «Аккаунт» → «О приложении»: поддержка, «Написать нам» (почта), условия, политика,
  версия. Гостю — кнопка ⓘ в «Профиле».

Новая версия документов: поправить `docs/public`, увеличить `LegalDocuments.version`
(`DaladaCore/Legal.swift`) — приложение попросит согласие ещё раз.

### Код

- База: `migrations/…_terms_consent.sql`; тесты — `17_terms_consent.test.sql` (6 проверок), всего — 363.
- `.github/workflows/pages.yml`, `docs/public/*.html`.
- `DaladaCore/Legal.swift`, `UserProfile.termsVersion`; `Backend/LegalAPI.swift`;
  `SessionStore.needsConsent`, `acceptTerms()`; `AppFeature/LegalViews.swift` (согласие, ссылки,
  «О приложении»).

### Как проверить

1. Откройте страницы по адресам выше (после включения Pages) — три языка, ссылки между страницами.
2. Установите сборку, войдите: сначала «Условия и конфиденциальность», «Продолжить» неактивна,
   пока не включён переключатель. Ссылки открывают страницы на языке приложения.
3. «Профиль» → «…» → «Аккаунт» → «О приложении»: ссылки и «Написать нам» открывают почту.
4. Выйдите — в «Профиле» ⓘ → «О приложении».

## M6d. Пуш-уведомления

### Что приходит

| Событие | Кому | Текст (пример) | По нажатию |
|---------|------|----------------|------------|
| Ответ в обсуждении | Автору обсуждения и автору процитированного ответа | «Ответ: Дорога» — «@bob: Через мост» | Обсуждение |
| Запрос в друзья | Получателю | «Запрос в друзья» — «@bob хочет добавить вас в друзья» | Профиль |
| Запрос принят | Отправителю | «Новый друг» — «Айгерім теперь у вас в друзьях» | Профиль |

Не себе и не между заблокированными; на языке телефона. Разрешение приложение спрашивает после
первого запроса в друзья, обсуждения или ответа (и в «Аккаунт» → «Уведомления»). Если приложение
открыто — баннер сверху. При выходе из аккаунта телефон перестаёт получать его уведомления.

### Как устроено

Триггеры кладут уведомления в очередь `private.push_outbox` → раз в минуту pg_cron вызывает Edge
Function `push` (через pg_net) → функция отправляет в APNs и отчитывается. Пока ключ и секреты не
настроены, уведомления ждут в очереди сутки и пропадают — приложение работает как раньше.

### Настройка (один раз, ~15 минут)

1. **Ключ APNs.** [developer.apple.com](https://developer.apple.com/account/resources/authkeys/list)
   → Keys → «+» → название «Dalada Push», галочка **Apple Push Notifications service (APNs)** →
   Configure → Environment: **Sandbox & Production** → Save → Continue → Register → **Download**
   (файл `AuthKey_XXXXXXXXXX.p8`, скачать можно один раз). Запомните **Key ID** и **Team ID**
   (Membership → Team ID). Ключ — секрет: только в Supabase, не в чат и не в репозиторий.
2. **Секреты функции.** Supabase → Edge Functions → **Secrets** → добавить:
   - `APNS_KEY_ID` — Key ID;
   - `APNS_TEAM_ID` — Team ID;
   - `APNS_PRIVATE_KEY` — всё содержимое файла `.p8` (вместе со строками `-----BEGIN…`);
   - `PUSH_WORKER_SECRET` — любая длинная случайная строка (например, из генератора паролей).
3. **Vault** — Supabase → SQL Editor → выполнить (подставьте свой project ref и ту же строку):
   ```sql
   select vault.create_secret('https://<project-ref>.supabase.co/functions/v1/push', 'push_function_url');
   select vault.create_secret('<та же строка, что PUSH_WORKER_SECRET>', 'push_worker_secret');
   ```
4. **Деплой функции из GitHub.** supabase.com → Account → **Access Tokens** → Generate. В GitHub →
   Settings → Secrets and variables → Actions: `SUPABASE_ACCESS_TOKEN` (токен) и
   `SUPABASE_PROJECT_REF` (id проекта из адреса дашборда). Потом Actions → **Edge Functions** → Run
   workflow (дальше — сам при изменениях в `supabase/functions` в `main`).

Проверка: второй аккаунт отправляет вам запрос в друзья — через минуту приходит пуш. Если нет —
Supabase → Edge Functions → push → Logs и `select * from private.push_outbox order by id desc` (поле
`last_error`: `InvalidProviderToken` — неверные Key ID / Team ID / ключ, `BadDeviceToken` —
сборка из Xcode против production или наоборот).
