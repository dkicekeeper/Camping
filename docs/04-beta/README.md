# 04. Путь к бете

> Обновлено: 2026-09-30. Этапы 4 (спецификации) и 5 (реализация) идут вместе: каждая веха —
> короткая спецификация, код, тесты и сборка в TestFlight.

## Как работаем

- **Я** пишу код (iOS, SQL, Edge Functions), миграции и тесты базы. Базу проверяю здесь же:
  локальный Supabase, миграции с нуля, тесты pgTAP, линтер.
- **Вы** собираете iOS-приложение на Mac (Xcode 26), запускаете на симуляторе или телефоне,
  присылаете ошибки сборки и скриншоты, выкладываете сборки в TestFlight.
- Каждая веха заканчивается рабочей сборкой. Спецификация вехи — в этой папке (`M1-*.md` и т.д.),
  пишется в начале вехи.

## Упрощения на время беты

| Что | В архитектуре | В бете | Когда вернёмся |
|-----|---------------|--------|----------------|
| Базовая карта | Свои тайлы на Cloudflare R2, офлайн-пакеты | **OpenFreeMap** онлайн: бесплатно, без ключа и лимитов, можно в мобильных приложениях | M5 — офлайн для одного региона |
| Админка | React + Refine | **Supabase Studio**: модерация мест и жалоб прямо в таблицах | После беты |
| Приглашения | Универсальные ссылки на `dalada.app` | Ссылки `dalada://…` и QR-коды | Когда будет домен |
| Подтверждение телефона | Telegram Gateway | Выключено; первые 3 публичных места автора проходят модерацию | К бете или после |
| Локальная БД | Экраны читают только локальную БД, сеть её обновляет | Экраны ходят в сеть, при ошибке — кэш последних ответов; своё новое — через офлайн-очередь | M3: поездки и треки сразу пишутся в локальную БД |
| Загрузка в фоне | Фоновая `URLSession` и `BGTaskScheduler` | Очередь досылается при сворачивании и в фоновом обновлении iOS, пока что-то ждёт ([M2d](M2-checkins-catches.md#m2d-отправка-в-фоне)) | Фоновая `URLSession` — после беты, если длинные поездки с фото не успевают |

## M0. Фундамент — что сделано

**База (`supabase/`):**
- `migrations/…_foundation.sql` — PostGIS, pg_trgm, unaccent; закрытая схема `private`; профили
  (создаются автоматически при регистрации).
- `migrations/…_social.sql` — запросы в друзья, взаимная дружба, блокировки; единая функция
  видимости `private.can_view`; RPC: `send_friend_request`, `respond_friend_request`,
  `remove_friend`, `profile_by_username`, `my_friends`.
- `migrations/…_places_checkins.sql` — места (9 типов, видимость, приблизительная точка со
  стабильным смещением, модерация первых публичных мест) и чекины (подтверждение по расстоянию
  500 м, «не видимее места»); RPC `places_in_bbox`, `place_card`.
- `tests/database/01_visibility.test.sql` — 41 проверка: владелец, друг, чужой, заблокированный,
  гость × публичные, дружеские, секретные, приблизительные места; защита от поиска точки сужением
  области; права на колонки; чекины; блокировки; модерация. Проверено, что тесты ловят поломку.
- Права выдаются явно на каждую таблицу и колонку; чужие строки с координатами напрямую не читаются.

**iOS (`ios/`):**
- `project.yml` (XcodeGen), таргет `Dalada`, bundle ID `app.dalada.ios`, iOS 26, Swift 6.
- Пакет `Packages/DaladaKit`: модули `DaladaCore`, `DaladaUI`, `MapEngine` (MapLibre), `Backend`
  (supabase-swift), `AppFeature`; тесты `DaladaCoreTests`.
- Вкладки «Профиль», «Карта», «Места», «Лайфхаки» и «+» с быстрыми действиями (пока «Скоро»).
- Карта Алматинского региона (OpenFreeMap) с позицией пользователя.
- На профиле — карточка «Сервер»: проверяет соединение с Supabase и что миграции применены.
  С M2 она появляется только при проблеме (сервер не настроен или недоступен).
- Каталоги строк RU / KK / EN (казахский помечен «на вычитку»), временная иконка.
- `ci_scripts/ci_post_clone.sh` — для Xcode Cloud (генерация проекта и секретов).

**Задел для M1:** `migrations/…_usernames.sql` — правила username (формат, зарезервированные
имена, приведение к нижнему регистру) и RPC `username_available` для экрана онбординга; тесты —
`tests/database/02_usernames.test.sql`.

**CI:** `.github/workflows/supabase.yml` — миграции с нуля, линтер, тесты базы на каждое изменение `supabase/`.

## Что нужно от вас

### 1. Проект Supabase — ✅ создан (2026-09-29)

При создании: регион **Central EU (Frankfurt)**, «Automatically expose new tables» — **выключить**,
«Enable automatic RLS» — **включить**, пароль базы — в менеджер паролей.

### 2. Миграции в облачную базу — ✅ ветка `main` и GitHub-интеграция настроены (2026-09-29)

Каждое изменение в `main` применяет новые миграции к облачной базе. В `main` попадает только то,
что прошло тесты базы.

**Вариант A (рекомендую) — GitHub-интеграция.** Сейчас в репозитории одна ветка — рабочая
(`claude/…`), и GitHub считает её основной.
1. Создайте ветку `main` (из рабочей ветки или через pull request в новую `main`) и сделайте её
   основной в настройках GitHub. Могу сделать это сам, если разрешите.
2. Supabase → Project Settings → Integrations → GitHub: production branch — `main`, путь к
   Supabase-папке — корень репозитория (папка `supabase`).
3. Дальше каждое слияние в `main` применяет новые миграции к облачной базе.

**Вариант B — вручную с Mac:** `supabase link --project-ref <ref>` → `supabase db push`.

### 3. Первая сборка на Mac — ✅ собирается и работает на симуляторе (2026-09-29)

```bash
brew install xcodegen                      # один раз
cd ios
cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig
# впишите SUPABASE_HOST (без https://) и SUPABASE_KEY (publishable key)
xcodegen generate
open Dalada.xcodeproj                      # Run на iPhone-симуляторе (iOS 26)
```

**Один раз** включите git-хуки проекта — дальше после `git pull` Xcode-проект пересоздаётся сам,
когда это нужно (изменился `ios/project.yml` или добавились/удалились файлы в `ios/Dalada/`):

```bash
cd путь/к/репозиторию && git config core.hooksPath .githooks
```

Изменения в `ios/Packages/DaladaKit` (основной код) Xcode подхватывает сам: `git pull` → Run.

Проверка: 4 вкладки и «+», карта Алматы на вкладке «Карта», на «Профиле» нет карточки «Сервер» с ошибкой
(после применения миграций). Ошибки сборки присылайте текстом или скриншотом.

### 4. TestFlight (к концу M1)

**Без Mac** — сборка в GitHub Actions и установка через TestFlight: [testflight.md](testflight.md).
Ниже — вариант через Xcode.

1. App Store Connect → Apps → «+» → New App: имя «Dalada» (если занято — «Dalada: рыбалка и
   природа»), bundle ID `app.dalada.ios`, SKU `dalada-ios`, основной язык — русский.
2. Xcode → Product → Archive → Distribute App → App Store Connect → Upload.
3. TestFlight → Internal Testing: до 100 человек из вашей команды App Store Connect, без проверки
   Apple. Внешние тестеры по публичной ссылке — после Beta App Review (M6).
4. По желанию — Xcode Cloud: скрипт `ios/ci_scripts/ci_post_clone.sh` уже есть; переменные
   `SUPABASE_HOST` и `SUPABASE_KEY` задаются в настройках рабочего процесса.
