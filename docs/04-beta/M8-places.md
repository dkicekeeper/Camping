## Что делает приложение

| Где | Что |
|-----|-----|
| Сверху | Поиск по названию: без учёта регистра и «ё», прощает опечатки («водопат» → водопады). Чипы типов (водоём, точка ловли, стоянка, родник…) — можно выбрать несколько |
| «Мои места», «Сохранённые» | Переходы в начале вкладки (после входа). Сохранённые — свежие сверху, без сети — сохранённая копия |
| **Рядом со мной** | Чужие места по расстоянию. Позиция берётся, только если разрешение уже есть; иначе кнопка «Показать места рядом» — тогда iOS спросит разрешение |
| **Популярные** | Публичные места с чекинами, фото, отзывами и сохранениями за 30 дней; чем дальше, тем ниже (вдвое — на 25 км) |
| **Где были друзья** | Места, где отмечались друзья (если их чекины вам видны), по свежести; на карточке — кто был |
| **Подборки редакции** | «Водоёмы рядом с Алматы», «Стоянки с ночёвкой», «Родники», «Что посмотреть по дороге», «Платники и снасти» — ближайшие сверху |
| **Свежие отчёты** | Места с чужими чекинами за 30 дней, по свежести |
| **Новые места** | Чужие места за 90 дней (места редакции — в подборках, не здесь) |
| Карточка в подборке | Фото последнего видимого отчёта или значок типа, название, отметка редакции, тип, расстояние, оценка, «Отчёт 2 дня назад», «Были: …», закладка, если сохранено |
| «Все» | Полный список (до 100): фильтр по типам, сортировка (расстояние, оценка, свежесть отчётов, популярность, новые, название), переключатель «Список / Карта» |
| Карточка места | Закладка в панели — «Сохранить» / «Сохранено» (после входа, кроме своих мест) |

Пустые подборки не показываются. Гость видит поиск и все подборки, кроме «Где были друзья»;
сохранять места — после входа.

## Приватность

Всё — через те же правила, что у карты (`places_in_bbox`, `place_card`):

- в списки попадают только места, которые зритель видит (`private.can_view`, опубликованные или
  свои), без мест людей, с которыми есть блокировка;
- у чужого приблизительного места — смещённый центр и радиус; **расстояние и порядок «рядом» —
  тоже по смещённому центру**: иначе настоящую точку можно найти, двигая «мою позицию». Тест
  ставит зрителя в настоящую точку и проверяет, что первым идёт соседнее место, а не это;
- счётчики, «последний отчёт», фото и «кто был» — только из чекинов и фото, видимых зрителю;
- «Популярные» — только публичные места; в рейтинг идут публичные подтверждённые чекины, отзывы и
  сохранения (сами числа клиенту не отдаются);
- сохранить можно только видимое место; если оно потом стало недоступно, из «Сохранённых» оно
  пропадает. Таблица `saved_places` пишется только через `save_place`, читаются свои строки.

## Код

**База** (`supabase/migrations/…_places_discover.sql`):
- `saved_places` (+ `save_place`, `my_saved_places`; не больше 1000 на человека), подборки редакции
  `place_collections` / `place_collection_items` (клиенту — только через RPC; пять стартовых
  подборок собраны из мест @dalada, состав правит редакция в Supabase Studio);
- `places_discover(p_lon, p_lat)` — все секции одним ответом (по 10 мест);
  `places_search(p_query, p_types, p_sort, p_lon, p_lat, p_limit, p_offset)`;
  `place_collection(p_collection, …)`; общий тип строки `public.place_item`;
- тесты `tests/database/21_places_discover.test.sql` — 40 проверок: кто что видит (гость, чужой,
  друг, автор, заблокированный), огрубление и порядок по расстоянию, счётчики и фото только из
  видимого, друзья, сохранённые, подборки, ошибки. Всего тестов базы — 442.

**iOS** (`Packages/DaladaKit`):
- `DaladaCore/PlaceDiscovery.swift` — `PlaceItem`, `PlaceDiscovery`, `PlaceCollection`,
  `PlaceSection`, `PlaceSort`, `PlaceQuery`; тесты `PlaceDiscoveryTests`;
- `Backend/PlacesDiscoverAPI.swift` — подборки, поиск, подборка редакции, сохранённые, закладка;
- `AppFeature/PlacesStore.swift` — подборки, позиция, превью фото, кэш без сети;
  `AppFeature/PlacesViews.swift` — вкладка, карусели, полные списки, «Мои места», `SavePlaceButton`.

## Как проверить

1. «Места»: сверху поиск и чипы, ниже подборки редакции (около Алматы — водоёмы, родники…).
2. Если геопозиция ещё не разрешена — «Показать места рядом» → разрешить → появится «Рядом со мной»
   с расстояниями.
3. Поиск: «жасыл» → озёра Жасылколь; «водопат» → водопады; чип «Родник» сужает результат; меню
   сортировки — «По расстоянию», «По названию».
4. «Все» у подборки → список; «Карта» в панели — те же места на карте; тап — карточка.
5. Карточка места → закладка → «Сохранённые» в начале вкладки. Без сети «Сохранённые»
   открываются (сохранённая копия).
6. Со вторым аккаунтом-другом: отметьтесь в месте → у первого — «Где были друзья» и «Были: …».

## M8c. Галерея места

Фото посетителей — из их отчётов (чекинов) и уловов, без стоковых картинок.

| Где | Что |
|-----|-----|
| Шапка карточки места | Ряд из 12 последних фото; тап — на весь экран. Нет фото — шапки нет |
| «Все фото» | Сетка по три в ряд, свежие сверху, подгрузка при прокрутке (по 60). Фильтр: все / уловы / место |
| На весь экран | Листание свайпом; внизу — автор, дата отчёта, «Улов» или «Отчёт», номер фото; у чужого фото — «Пожаловаться» и «Заблокировать» (жалоба — на отчёт с этим фото) |

**Видимость** — как у фото в отчётах: место видно зрителю, а само фото проходит
`private.media_visible` — виден отчёт, у фото улова — и улов; с заблокированными фото не показываются.
Секретный отчёт или улов — фото видит только автор.

**Код.** База: `migrations/…_place_photos.sql` — RPC `place_photos(p_place, p_kind, p_limit, p_after)`;
курсор страниц — id последнего фото (у фото одного отчёта общее время, курсор по времени терял бы
их). Тесты `tests/database/22_place_photos.test.sql` — 16 проверок (гость, чужой, друг, автор,
заблокированный, секретный улов, фильтр, страницы). iOS: `DaladaCore/PlacePhotos.swift`,
`Backend/PlacesDiscoverAPI.swift` (`placePhotos`), `AppFeature/PlacePhotosViews.swift` (шапка, сетка,
просмотр), карточка места грузит первые фото вместе с отчётами.

**Как проверить.** Отметьтесь в месте с 2–3 фото (одно — к улову) → в карточке места наверху ряд
фото → «Все фото» → фильтр «Уловы» оставляет фото улова → тап — на весь экран с автором и датой.
Со второго аккаунта (не друга) отчёт «для друзей» не виден, и его фото в галерее нет.

## M8d. Карточка места: информация, правки, «Рядом», «Поделиться»

Из плана страницы места (`docs/02-plan/03-places.md`, «3.2», «3.7»; атрибуты — `02-map.md`,
«Атрибуты места»).

| Где | Что |
|-----|-----|
| «Свежие отчёты» | Сверху сводка: «За 7 дней: 12 отчётов, клёв в основном хороший» — по видимым отчётам (загружается до 50; если все за неделю — «больше 50») |
| **Информация** | Рыба, способы ловли (с берега, с лодки, спиннинг, фидер…), подъезд (асфальт, грунтовка, только 4×4, пешком, на лодке), стоимость (бесплатно / платно, цена ₸ и за что, контакты), удобства, связь, лучшие месяцы, особенности. У мест для рыбалки сначала рыба |
| Своё место | «Изменить»: название, тип, описание, «Информация», видимость и «приблизительно». Точку пока не двигаем. Публичное место у новых авторов снова уходит на проверку (как при создании) |
| Чужое публичное место | «Предложить правку» — те же поля, уходят только изменённые; «Сообщить о проблеме» — не та точка, закрыто, такого места нет, дубль, опасно. Комментарий для редакции. «На проверке», пока редакция не решила |
| **Рядом** | До 6 похожих мест в 30 км (рыбалка — к рыбалке, ночёвка — к ночёвке), ближайшие первыми; тап — карточка поверх |
| «Поделиться» | Ссылка `dalada://place/<id>` — откроет карточку у того, кому место видно. У чужого публичного места с точной точкой — ещё ссылка на карту (для тех, у кого нет приложения). У приватного места кнопки нет |

**База** (`migrations/…_place_info.sql`):
- атрибуты из приложения проверяются триггером: только известные ключи и значения (рыба — из
  справочника), длины и цена в пределах; служебные `source` и `osm` приложение не ставит и не меняет
  (отметку редакции не подделать); текст атрибутов проходит фильтр грубых слов (кроме приватных мест);
- `place_suggestions` — предложения правок и сообщения о проблемах; пишутся только через
  `suggest_place_change` (чужое публичное опубликованное место, которое человек видит; не больше 20
  в сутки; повторное того же вида обновляет открытое). Автор читает свои строки, остальные — никто;
- редакция в Studio: очередь `private.place_suggestion_queue`, принять — `select
  private.accept_place_suggestion('<id>')` (правка применяется к месту, атрибуты заменяются, служебные
  ключи остаются), отклонить — `private.reject_place_suggestion('<id>')`. «О проблеме» — только
  отметка: скрыть или удалить место редакция решает сама;
- тесты `tests/database/23_place_info.test.sql` — 50 проверок (ключи и значения, служебные ключи,
  фильтр слов, кто может предлагать, лимит, видимость предложений, решение редакции). Всего тестов
  базы — 508.

**iOS:** `DaladaCore/PlaceInfo.swift` (`PlaceAttributes`, `PlaceReportsSummary`, `PlaceLink`,
`PlaceEditDraft`, `PlaceChanges`, `OwnPlaceDraft`; тесты `PlaceInfoTests`), `Backend/PlacesAPI.swift`
(`ownPlace`, `updatePlace`, `suggestPlaceChange`, `openPlaceSuggestions`),
`AppFeature/PlaceInfoViews.swift` (сводка, «Информация», поля формы, правка своего места, предложение,
«Рядом»), ссылка на место — в `RootView`.

**Пока нет:** уведомление автору места о предложении и человеку о решении, очки за принятые правки,
перенос точки и обложка в правке, мини-карта с точкой подъезда.

**Как проверить.**
1. Своё место → «Добавить информацию» → рыба, подъезд, «Платно», 2000 ₸ за сутки, месяцы → «Сохранить»
   → в карточке блок «Информация».
2. Отметьтесь в месте с клёвом «Хороший» → над отчётами «За 7 дней: 1 отчёт, клёв в основном хороший».
3. Чужое публичное место (например, место редакции) → «Предложить правку» → поменяйте название →
   «Отправить» → «Ваше предложение на проверке». «Сообщить о проблеме» → «Закрыто».
4. Внизу карточки — «Рядом»: соседние места того же рода; тап открывает их карточку.
5. «Поделиться» в панели → отправьте себе в «Заметки» → тап по ссылке `dalada://place/…` открывает
   карточку.
